# AI-SAST ツール(local-ai-sast)の試験(`ai-sast-trial.yml`)

他人の AI-SAST ツール [sohampatil99/local-ai-sast](https://github.com/sohampatil99/local-ai-sast) を、
このリポジトリの「正解つきの的」(`security-scan/sqli-lab/vulnerable_app.py`、11種類の脆弱性と修正版)に
かけて、**コードを読んで探す方式(SAST)の精度**を、数字で比べるための、試験用のワークフロー。

> ⚠️ local-ai-sast には、**`LICENSE` ファイルが無い**(2026-10-28 のコミット時点)。ここでは、
> 「動かして評価する」だけで、このリポジトリへの取り込みや再配布はしない。

## 何をするか

1. local-ai-sast を、**固定したコミット**(`67cca21`)で取得する。
2. 的を、`vulnerable_app.py` だけを入れた別のフォルダに置く。
3. **ルールだけ**(AI なし)でスキャンする。
4. Ollama(公式の Docker イメージ)を起動して、小さなモデルを取得し、**AI あり**(`--ai`、`--ai-review`)で
   スキャンする。
5. `security-scan/sqli-lab/compare_sast_ground_truth.py` で、正解と比べる(脆弱版を検出したか、修正版を誤検知
   したか)。結果は、ジョブの要約と、アーティファクト(`ai-sast-trial`)に出る。

## 実行のしかた

- GitHub の Actions タブで `ai-sast-trial` を選び、「Run workflow」(モデル名を、変えられる)。
  ただし、`workflow_dispatch` は、ファイルが `main` にあるときだけ使える。
- このワークフロー自身(または比較スクリプト)を変更した PR では、動作確認のために、一度、自動で動く。

## 安全のための決めごと

- 他人のコードを CI で実行するため、**取得するコミットを固定**し、権限は読み取りだけ(`contents: read`)。
- 手動実行が基本。毎回の push では、動かさない。
- モデルの名前は、環境変数経由でシェルに渡す(コマンドへの埋め込みを避ける)。

## 検証状態(正直に)

- **ルールだけの結果**(クラウド環境で、2026-10-31 に実行): 指摘 9 件。11種類のうち **5 件を検出、6 件を見逃し、
  修正版の誤検知 2 件**(`/file_safe` の `realpath` による自前の検査と、`/fetch_url_safe` の独自の関数による
  検査を、認識できなかった)。見逃したのは、反射型 XSS、格納型 XSS、CSRF、IDOR、マスアサインメント、
  アカウント列挙。
- **AI ありの結果**(GitHub Actions、2026-10-30、モデル `qwen2.5-coder:3b`、CPU のみ、run 41114366000): AI ありの
  スキャンは **385 秒**(ルールだけは 0.03 秒)で、時間内(上限 35 分)に終わった。12 件の指摘(AI が `false_positive`
  と判定した 1 件を含む)。比較(AI の判定を考慮した数え方):

  | | ルールだけ | AI あり(3B) |
  |---|---|---|
  | 検出 | 5 / 11 | 6 / 11(うち「要確認のみ」1) |
  | 見逃し | 6 / 11 | 5 / 11 |
  | 修正版の誤検知 | 2 | 1 |

  - AI ありで増えた検出は、**アクセス制御の不備(IDOR)**(228 行目)。ただし、AI の判定は `needs_review`(要確認)。
  - `/fetch_url_safe` の SSRF は、AI が `false_positive` と判定して、打ち消した。比較スクリプトは、これを
    検出にも誤検知にも数えず、別に一覧する。
  - 3B のモデルは、誤りもある: `/file_safe` のパストラバーサル(自前の `realpath` の検査がある)を `true_positive` と
    判定した(誤り)。`/login` の「ハードコードされたパスワード」(SQL 文への値の埋め込みで、固定値ではない)も、
    `true_positive` と判定した(誤り)。
  - 見逃しのまま: 反射型 XSS、格納型 XSS、CSRF、マスアサインメント、アカウント列挙。
  - 1 回の実行(LLM の出力は、毎回、少し変わる)で、1 つのモデル、1 つのアプリの結果。一般化はできない。
- **比較スクリプトの数え方**: AI のレポートでは、`false_positive` を打ち消し扱いにし、脆弱版への指摘がすべて
  `needs_review` なら「検出(要確認のみ)」とする(AI なしのレポートには、影響しない)。この数え方は、実際の
  Actions のログの内容を写した JSON で確認した。
- 1 つのアプリ(348 行)での結果で、一般化はできない。
