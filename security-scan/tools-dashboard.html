① 依存関係・アドバイザリ ② OS/カーネル確認 ③ 個別インシデント対応 ④ 露出・ネットワーク棚卸し ⑤ 集計・修正提案 ⑥ 外部の推奨ツール

このページについて

本リポジトリの scripts/*.py・netcheck/ に点在する「自分の環境を確認する」ツールを 1か所にまとめた索引。各カードの「詳細」リンク先は、そのツールの背景・できること・できないこと・ 検証状況を日本語でまとめたノートファイル。個別ツールの実行結果を集めて横断表示する機能はない (各ツールはそれぞれ単独で、自分が管理するホスト上で実行するもの)。

① 依存関係・アドバイザリ確認 Dependency / advisory lookup

パッケージの既知脆弱性照合と、アドバイザリの正確な転記。ネットワークアクセスは読み取り専用のAPI呼び出しのみ。

dep_cve_check.py モックで検証済み

scripts/dep_cve_check.py

requirements.txt(pip、==固定行)と npm の package-lock.json を読み、公開の脆弱性データベース OSV.dev に照合する。 出力は SARIF 2.1.0(vuln_triage.htmlにそのまま読み込める)。

python3 scripts/dep_cve_check.py --requirements requirements.txt --out dep_cve.sarif
python3 scripts/dep_cve_check.py --npm-lock package-lock.json --out dep_cve.sarif
標準ライブラリのみモックAPIで検証/実APIは未検証

ghsa_lookup.py モックで検証済み

scripts/ghsa_lookup.py

GitHub Security Advisory(GHSA)の構造化データ(影響版・修正版・CWE・CVSS)を GHSA ID または CVE 番号から取得し、要約せず転記するだけで Markdown 出力する。 過去にLLM要約で2件のCVEを取り違えた誤りを防ぐ目的で作成。

python3 scripts/ghsa_lookup.py --ghsa GHSA-xjw9-4gw8-4rqx --out report.md
python3 scripts/ghsa_lookup.py --cve CVE-2026-26030 --out report.md
標準ライブラリのみこのセッションのGitHubスコープ制限で実API未到達

② OS・カーネル確認 OS patch / kernel version checks

管理している機器の更新状況・カーネルバージョンを読み取るだけ。更新の適用や設定変更は一切しない。

os_patch_check_linux.py / _windows.py 実機では未検証

scripts/os_patch_check_linux.py / scripts/os_patch_check_windows.py

Linux(RHEL系、dnf updateinfo list security)と Windows (Get-HotFix、--windows-pendingでWindows Update APIも)の 未適用/適用済み更新を確認。出力は SARIF 2.1.0。

python3 scripts/os_patch_check_linux.py --out os_patch.sarif
python scripts/os_patch_check_windows.py --windows-pending --out os_patch.sarif
標準ライブラリのみ

→ 詳細ノート

linux_kernel_infinitycore_check.py サンドボックスで実行確認済み R21

scripts/linux_kernel_infinitycore_check.py

実行中のカーネル(uname -r)と/etc/os-releaseを、 「Infinity Core」(6件のLinuxカーネルLPE脆弱性チェーン、CVE-2026-98260等)と照合。 ディストリビューションごとのバックポート差異のため、単純な数値比較による断定はしない (例外: CloudLinux CL9のみ、正確な修正済みビルドが判明)。

python3 scripts/linux_kernel_infinitycore_check.py --out infinitycore.sarif
標準ライブラリのみ

java_cacerts_emudhra_check.py 実JDKで実行確認済み R14

scripts/java_cacerts_emudhra_check.py

ローカルJDKの cacerts(信頼ストア)に、eMudhra侵害CA(2026-10、8件の中間CA 秘密鍵侵害)に連なるルートCAがあるかを確認し、java -versionをIPA公表の 「脆弱な版」一覧(CVE-2026-91403)と突き合わせる。

python3 scripts/java_cacerts_emudhra_check.py --out java_cacerts.sarif

④ 露出・ネットワーク棚卸し Exposure / network inventory

自社が管理するIP範囲だけに対象を限定する、棚卸し用ツール群。脆弱性スキャナではない。

netcheck.py ブラウザUIあり

netcheck/netcheck.py

自社IP・ホストへの「確認だけ」のチェック(開いているポート、バナー、HTTPSヘッダ/証明書状態、 管理画面らしきURLの応答有無)。127.0.0.1限定でブラウザ画面を提供し、起動ごとのトークンが必要。 対象は既定で社内プライベートIP範囲のみ。脆弱性を突く動作は一切行わない。

ブラウザUI許可範囲外は拒否

→ 利用の流れ(ウォークスルー)

zgrab2_guard.py 実機では未検証

scripts/zgrab2_guard.py

能動スキャナ zgrab2 自体には許可範囲を制限する機能が無いため、標準入力の対象を netcheck と同じ許可範囲判定で検査し、範囲内のものだけを zgrab2 の入力形式で出力するガード。 1件でも範囲外が混ざると、全体を出力せず終了コード2で止まる。

cat targets.txt | python3 scripts/zgrab2_guard.py | zgrab2 http
何にも接続しないnetcheck/config.jsonのallowed_rangesを使用

⑤ 診断結果の集計・修正提案 Summarize & suggest (never auto-applies)

他のスキャナ(Semgrep/Trivy/gitleaks/ZAP等)の結果を受け取る側のツール。単体では何も検査しない。

summarize.py

scripts/summarize.py

Semgrep/Trivy/gitleaks/ZAPのJSON結果を集計。出力形式はMarkdown(CIサマリ用、既定)/ Elastic(ECS NDJSON)/Datadog(Logs JSON、検知ルールR1–R21が載るSIEM側へ流す用)。

python3 scripts/summarize.py results
python3 scripts/summarize.py results --fail-on high

CIワークフロー(.github/workflows/security-scan.yml)で使用。

patch_suggest.py 自動適用なし

scripts/patch_suggest.py

診断結果(Semgrep/SARIF/Trivy)から修正案をdiffとして作る。自動適用はしない (1件ずつ人がy/N確認)。Semgrep指摘は自前LLMに最小限のdiffを作らせ、Trivyの脆弱性(FixedVersionあり) はLLMを使わずマニフェストのバージョン表記を書き換えるだけ。gitleaks(秘密情報)は対象外、 手動ローテーションを案内するのみ。秘密情報の値はLLMに送らない。

⑥ 外部の推奨ツール Recommended external tools (not vendored in this repo)

本リポジトリでは実装せず、既に公開・保守されている第三者ツールへのリンクに留めるもの。

php2shell-scanner 外部・第三者 R15

github.com/aancw/php2shell-scanner

PHP2Shell(CVE-2026-109618/CVE-2026-109619)の確認専用スキャナ(Go製、静的バイナリ)。 url(ブラックボックス)/local(このホスト)/ssh(リモートホスト)の3モードで、バージョンだけでなく 実際の悪用可否を左右する設定(session.upload_progress・SAPI・memory_limit等) まで確認する。本リポジトリのsqli-lab/auto_vuln_scanner.pyの check_php2shell()(バージョン比較のみ)より詳細な確認が必要な場合に推奨。 本リポジトリ側では未実行・未検証 — 利用前に公式リリースのSHA256SUMSを確認すること。

確認・検知の設計に限定。攻撃の実行手順や安全機構の回避方法は含めない。各ツールの詳細・検証状況は 個別ノートファイル、または README.md / README.ja.md 「自分の環境を確認するツール」節を参照。
