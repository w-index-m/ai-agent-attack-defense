③ 予防コントロール Preventive controls

検知の前段で効く固定策。優先度順。

  • 送信ドメイン allowlist — サーバ系からの LLM/メッセージングは既定遮断。
  • コンテナ admission control — 特権cap・host net・未署名/未知イメージを禁止。
  • 攻撃面最小化 — 管理画面の隔離、DB/サービスをネット直結にしない（netcheck の RISKY ポート群）。
  • 決済・機微ページの CSP — skimmer/カード窃取コード注入の防止。
  • LLM 利用の監査・ガバナンス — 安全機構の除去/迂回の試行を検知・通報。

④ スキル機構とガバナンス Skills & governance / T1562

ネットワーク/ホストの検知(R1–R7)では捕まえにくい「エージェント/LLM の使い方そのもの」を統制・監査する層。MITRE T1562（防御の無効化）に対応。

スキルとは／なぜ危険か

スキル＝エージェントに後付けする「指示＋ツール権限＋ワークフロー」の束。Hermes は自己改善ループで自動生成・改良する。危険なのは、スキル内容を“信頼された上位の指示＋権限”として取り込む点。Gambit の事例では本体コードを変えず、攻撃用スキル(121中78が攻撃目的)＋自身の安全フィルタを外すスキルを上乗せしただけで司令塔化した。実質「信頼された指示＋権限を外部注入する口」＝サプライチェーン＋プロンプトインジェクションの二重の攻撃面。

ガバナンスが要求すること

  • 不可変の安全層：安全強制をスキル/モデルの外側で（書き換え不能に）。CVPの“不変の一線”が実例。
  • スキル allowlist・出所管理：署名/レビュー済みのみ許可、未知は既定で停止。
  • ツール権限の最小化＋ブローカー経由：権限はポリシーが決める。拡大は人の承認。
  • 改ざん耐性の監査ログ：プロンプト/ツール/スキル/安全設定変更を追記のみで記録。
  • 高リスク操作は人間承認(HITL)。
  • 検知と相関(R6)：下の監査イベントを R1/R4/R7 と突き合わせる。

監査イベント G1–G6（ガバナンス層）

ネットワーク/ホストの R1–R7 とは観測点が異なり、アプリ/監査ログ層（エージェント監査ログ・スキルレジストリ・LLM/ツールゲートウェイ・ログ基盤）で見る。

ID監査イベントデータソース優先度対応
G1スキルの導入・自動生成・自己改変エージェント監査ログ / スキルレジストリ高出所・署名・レビューを確認。未承認は隔離。
G2安全設定/ガードレールの変更・無効化の試行ポリシーゲートウェイ高外側の安全層で拒否。試行を即エスカレーション。
G3プロンプト/ツール呼び出しに迂回意図LLMゲートウェイ監査高ガバナンス審査。セッションを保全。
G4監査ログの欠落・停止ログ基盤ヘルス高ログ自体への攻撃を疑い復旧・保全。
G5ツール権限の拡大要求/付与ツールブローカー監査中最小権限に照合。拡大は人の承認。
G6サブエージェント大量スポーン/権限拡大の構成変更プロセス/エージェント・テレメトリ中R7 と相関。

兆候の存在と対応方針のみ。安全機構の回避方法は含めない。詳細は defense-detection-notes.md §7。

⑤ CVP（Cyber Verification Program）対応 Anthropic

活動をどのティアで正規化するか。詳細は cvp-readiness.md。

Defense Access
防御（SOC/IR/マルウェア解析/脆弱性検証）。個人研究者も可・審査数日。本リポの防御ツール＋解析＋検知ルールが射程。
Red Team Access
認可されたペンテスト（組織のみ・数週間）。Cairn ラボ運用はここ。隔離設計・ランブック・mock検証が統制証拠。
Specialized Access
安全重要システム（電力/通信/金融/政府網）。米政府連携が必要。

不変の一線：物理被害・大規模妨害・ランサム・安全系無効化はブロック対象。
