# サンドボックス防御モデル — スキャンパターン別（日本語）

English version: [`sandbox-defense-model.en.md`](sandbox-defense-model.en.md)

実行環境（例：Claude Code の cloud サンドボックス）のような**使い捨て・最小権限・egress 制限**の基盤に、
各種スキャンをかけたら設計上どうなるかを、**防御・教育の観点**で整理したもの。
検知・防御の設計に限定し、攻撃の実行手順や安全機構の回避方法は含まない。

> ⚠️ 重要（認可の境界）：運用基盤そのもの（他者が運用するインフラ）への脆弱性スキャン・侵入テストは、
> 利用者であることだけでは認可されない。実スキャンは**自分が所有／認可した対象**に限る。
> 運用者（例：Anthropic）のシステムを検証したい場合は、**責任ある開示 / バグバウンティ**の
> 定められたスコープと交戦規則に従うこと。本書は実スキャンを伴わない概念整理である。

## スキャンパターン別：狙い / 堅牢な基盤での受け止め / 対応する検知

| # | パターン | スキャンの狙い | 堅牢な基盤での受け止め | 対応する検知 |
|---|---|---|---|---|
| ① | ポート/サービス（nmap 系） | 開放ポート・サービス・バナー・旧版の列挙 | 利用者向けに公開サービスを持たない。外向きはプロキシ allowlist のみ。raw socket は権限なしで不発 | R3（偵察列挙） |
| ② | Web 脆弱性（ZAP/nuclei 系） | 認証・入力処理・ヘッダ/CSP・既知CVE | 公開 Web アプリが無ければ対象が無い。自前ステージング時のみ意味を持つ | R3、Web 4xx 集約 |
| ③ | コンテナ/権限昇格・エスケープ | 特権・危険 cap・host net・カーネル欠陥でホストへ脱出 | 特権分離・最小 cap・使い捨て。privileged/NET_RAW は既定で無く、足場も残らない | R2（特権コンテナ）、G5（権限拡大） |
| ④ | 内部NW/横移動・メタデータ探査 | 内部レンジのスイープ、169.254.x から資格情報窃取 | egress は allowlist 限定、内部/メタデータ/リンクローカルは遮断方向 | R1/R4（想定外 egress）、R6（相関） |
| ⑤ | シークレット/依存/コード（gitleaks/Trivy/Semgrep） | ハードコード鍵・脆弱依存・危険コード | これは“基盤”でなく“コード”が対象 → 自分のリポジトリに正規に実行できる | 事前防御(CIゲート) + トリアージ |
| ⑥ | 永続化・C2 的挙動 | cron/サービス常駐、外部へ指令通信 | ephemeral で常駐の意味が薄い。外向きは allowlist 制限 | R5（永続化）、R4（C2）、G1–G6 |

## 「使い捨て（ephemeral）」の正体 — 作り直す ≠ 実装し直す

起動ごとに**新しく立ち上げ直される（re-instantiate）**のは正しいが、「**実装し直す（コードを書き直す）**」
のではなく、**固定のレシピ（ベースイメージ＋setup スクリプト/設定）から、まっさらなインスタンスを毎回生成する**。

- **毎回フレッシュ**：コンテナは使い捨て。リポジトリも新規クローン。終了/無操作で丸ごと破棄され、前回の状態は持ち越されない。
- **毎回“同じ”**：土台は固定イメージ/設定。中身がランダムに変わるわけではなく、同じ構成が再現される。

### セキュリティ上の意味
- **ephemeral が守るもの＝「永続性・足場」**：仕込んでもセッション終了で消える。永続化(R5)・常駐C2(⑥)・横移動の足場が残らない。居座りが構造的に困難。
- **ephemeral が守らないもの＝「攻撃面そのもの」**：毎回同じイメージ＝毎回同じ攻撃面。弱点があれば“作り直し”では消えず、毎回同じように存在する。直すにはイメージ/設定の更新（パッチ）が必要で、再起動で勝手に消えるわけではない。

> まとめ：「毎回新品」=「毎回安全」ではない。**使い捨ては“居座り”を防ぐが、“弱点の有無”は
> 土台の作り込み（最小権限・分離・egress allowlist・パッチ）で決まる。**

## “なぜ効きにくいか”の共通原理（構造的封じ込め）

1. **最小露出**（公開サービスを持たない）→ ①②が空振り
2. **特権分離・最小 cap**（privileged/NET_RAW 無し）→ ③が成立しにくい
3. **egress allowlist＋内部/メタデータ遮断** → ④が到達不能
4. **使い捨て（ephemeral）** → ③⑥の足場が残らない
5. **固定リソース枠** → 乱用の影響を局所化

この5原則は、検知ルール R1–R7／G1–G6 の“裏返し”でもある。攻撃側が狙う各パターンに、基盤側は
「構造的封じ込め」で、SOC 側は「逸脱の検知」で応える——攻守が同じ観測点を共有する。

> 本書は防御・検知の設計に限定。攻撃の実行手順や安全機構の回避方法は含めない。
