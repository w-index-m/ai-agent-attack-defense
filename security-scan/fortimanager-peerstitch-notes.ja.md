# FortiManager侵害とPEERSTITCHインプラントの分析（一次情報）

English: [`fortimanager-peerstitch-notes.en.md`](fortimanager-peerstitch-notes.en.md)

（2026-10-14公開）の分析。**本件にAIエージェントの関与は一切記載されていない**（伝統的なAPT型の侵入）。

## 1. 概要

- 対象：ある通信事業者（マネージドサービスプロバイダ）。2024年9月に発生した侵入を、Unit 42 が
  **CL-STA-0954**（別名 UNC5820）として追跡。
- 初期侵害：中央集中管理機器である **FortiManager** を、**CVE-2024-47575**（通称 FortiJump）で侵害。
- この1台から、**500台を超える配下のFortiGateファイアウォール**の実行中設定・暗号材料・データベースを
  含むアーカイブを持ち出された。これらの機器は、被害組織自身のインフラと、**その顧客のネットワーク**
  の両方を保護していたもの。
- その後、長期的なアクセス維持、ネットワークトラフィックの傍受、VPNセッションの確立、バックドアの
  配備、別の権限昇格脆弱性（**CVE-2025-61624**）の悪用と進行し、新種のメモリ常駐型マルウェア
  **PEERSTITCH** の配備に至った。

## 2. 侵入の経緯

### 2.1 初期侵害とネットワーク構成情報の窃取（CVE-2024-47575）

- CVE-2024-47575（FortiJump）は、FMG-Access（TCP 541）管理チャネルへの細工されたリクエストで、
  未認証のリモート攻撃者が任意コマンドを実行できる脆弱性。
- 攻撃者は、外部インフラから、`localhost`という名前の不正な仮想FortiGate機器（シリアル番号
  `FMG-VMTM23017412`）をFortiManagerに登録。
- 機器登録の直後、`.tm`という名前の設定アーカイブを生成し持ち出した。中身には：
  - FortiManager自身のシリアル番号と、全登録機器との管理関係
  - **500台を超えるFortiGateファイアウォール**の実行中設定ファイル一式
  - 中央管理用SQLiteデータベース（`global.db`：管理ドメイン・グローバルオブジェクト・ポリシーパッケージ、
    `revinfo.db`：機器のリビジョン情報）
  - 500台超のシリアル番号と、それぞれの公開IPアドレスの一覧
  - 内部ネットワークのトポロジマップ、ルーティングテーブル、インターフェース設定
  - 暗号化された管理者・ローカル・SSL/VPN認証情報
  - 公開証明書・秘密鍵を含む暗号学的信頼材料

### 2.2 偵察とトラフィックの傍受

- 侵害したFortiManagerを使い、配下の複数のFortiGateに**無許可のスニファー設定**をプッシュ。
- 平文のHTTPトラフィックと、Telnet制御・ライセンス管理・制御パネル等、11種類の特定ポートを対象に、
  認証情報の傍受とネットワーク構成のマッピングを実施。
- さらに後続の偵察で、TFTP（UDP 69）、RADIUS/RADIUS-Accounting（UDP 1812/1813）、LDAP（TCP 389）を
  標的にしたパケットキャプチャルールを、境界ファイアウォールに追加配備。

### 2.3 認証情報の復号と再侵入

- 持ち出した設定ファイル内の認証情報は、**可逆な暗号文（reversible ciphertext）**として保存されており、
  総当たりで復号に成功。
- 復号した正規の認証情報で、外部のステージングインフラから、境界FortiGateへの**無許可のSSL/VPNセッション**
  を確立し、内部の管理セグメントへの認証済みアクセスを獲得。

### 2.4 権限昇格（CVE-2025-61624）とPEERSTITCHの展開

- CVE-2025-61624は、FortiOSの `system.auto-script` 機能における**パストラバーサル**。auto-scriptの
  オブジェクト名が無害化されておらず、`../../../../setup` のようなトラバーサル文字列を含む名前を使うと、
  スクリプト本体を任意の場所に配置できる。スクリプトは auto-script エンジンの権限（root）で実行される。
- これにより、管理者権限（super_admin含む）からOS側のroot権限への昇格が可能になる。FortiOSの管理者は、
  本来シェルアクセスもファイルシステムへの直接制御も持たない制限されたCLI内で動くが、その下で動く
  デーモン群はrootで動いているため。
- この経路で、PEERSTITCHの初段ローダーが配備された。

## 3. PEERSTITCHインプラントの技術的特徴

- **64bit Linux ARM64実行ファイル**、C言語製、glibc静的リンク。ディスクに永続的なバイナリを残さず、
  リスニングポートも開かず、アウトバウンド接続も自ら開始しない（＝従来のエンドポイント/ネットワーク
  検知に強い耐性を持つ）、**「一度きりのメモリパッチ型インジェクタ」**。
- 標的は2つのFortiOSコアデーモン：`/bin/miglogd`（システム・トラフィックのログ記録デーモン）と
  `/bin/iked`（IKE/IPsec VPNサービスデーモン）。
- **配布・展開の流れ**：CVE-2025-61624でプッシュした `../../../../setup` が、5つのファイル
  （環境準備スクリプト、Emscripten JS/WASMランタイム、展開オーケストレータースクリプト、
  ARM64 ELFバイナリ本体）を外部から取得し、実行。
- **プロセスへの寄生**：`/proc/` を走査して両デーモンのPIDを特定 → `/proc/<pid>/maps` でメモリ配置を
  把握 → `ptrace(PTRACE_SEIZE)` でアタッチ → レジスタ状態を取得 → `mmap` システムコールで16KBの
  RWX（読み書き実行可）メモリ領域を動的に確保 → そこに1,344バイトの注入ペイロードを書き込み。
- **デーモン間の秘匿IPC**：ネットワークソケットやディスクファイルを使わず、**両デーモンのメモリ間で
  直接データをやり取りする**仕組みを構築。各デーモンが通常処理するトラフィックの中から、特定のポート
  番号（8550）とIPアドレス（169.254.0.1、リンクローカルアドレス）という「目印」を文字列検索で探し、
  見つかるとセッショントークンを抽出。`/proc/<counterpart_pid>/mem` への直接書き込みで、もう一方の
  デーモンのメモリに受け渡す。`iked`側は、該当するタグが見つかると、通常のFortiOSセキュリティ検証を
  バイパスする代替の実行経路を取る。
- **改ざん検知の無効化**：3箇所の静的オフセットに、ARM64の `MOV X0, X0`（実質的なNOP）命令パッチを
  適用し、動作を変更。20バイトのトランポリンパッチで、確保したRWXバッファへ実行を誘導。

## 4. Apache mod_md（ACME）を悪用したリバースシェルC2

- PEERSTITCHと並行して、FortiGate機器に標準搭載されているApacheの `mod_md`（証明書自動管理用
  モジュール、ACMEプロトコルを使用）を兵器化。
- `../../tmp/apache2/conf/md-acme.conf` というauto-scriptオブジェクトを配置し、攻撃者の外部ACME
  サーバーへ問い合わせを向ける不正な設定を注入。
- DNS-01チャレンジのドメイン名フィールドに**シェルコマンドを注入**し、`MDChallengeDns01` が
  `/bin/node` にマッピングされていることを悪用して、SSHベースのリバースシェルを確立。
- `MDRenewMode always` の設定で、この不正な証明書更新チャレンジを**継続的に再実行**させ、永続的な
  アウトバウンドのリバースシェル通信を維持。

## 5. 管理プラットフォームへのなりすまし（FortiGate→FortiManager連鎖）

- FGFM（FortiGate-FortiManager間通信、TCP 541）は、機器シリアル番号に基づく暗号学的信頼材料で検証される。
  初期侵害時に持ち出したアーカイブには、この材料と、全配下機器のシリアル番号・管理関係が含まれていた。
- 外部インフラからのFGFM通信で、`FortiGateCloud` という管理者アカウント（被害組織はFortiManager Cloud
  テナントを運用しておらず、本来存在しないはずのアカウント）が、複数の配下機器から実行中設定を
  ダウンロードしたことを確認。
- Unit 42 は中程度の確度で、正規のFortiManagerになりすましたと評価（CVE-2024-26009による認証バイパス、
  または窃取した信頼材料の直接再利用のいずれか、または両方の可能性）。

## 6. アンチフォレンジック・証跡消去

- `killall -9 miglogd` / `killall -9 syslogd` で、悪性auto-script実行前にログ生成を停止。
- `diagnose debug crashlog clear` で、メモリ注入試行時に生成されたクラッシュログを消去。
- 不正な管理者アカウント・VPNグループ・auto-scriptオブジェクトを、実行直後に自動削除。
- `md-acme.conf` を、このファイルによくある無害な文字列で上書きし、リバースシェル設定を隠蔽。
- `lldprx`（インジェクタ本体）は、実行後に自身のバイナリをディスクからアンリンクし、ステージング用
  プロセスを探して終了させる自己削除機能を持つ。
- トンネル管理インターフェースのログテレメトリに、悪性活動の期間中、断続的な欠落が観測された。
  Unit 42 は中程度の確度で、意図的な妨害（CVE-2024-26008経由の可能性）と評価しているが、トリガーと
  なった通信自体はログに残っておらず、メカニズムは確認できていない。

## 7. 検知の機会（Unit 42 Table 2 の要約）

| 検知面 | 痕跡・指標 |
|---|---|
| 揮発性メモリ | `/bin/miglogd`・`/bin/iked` の `/proc/<pid>/maps` に、rwxp権限の匿名16KB領域がないか |
| デーモンの完全性 | 特定の静的オフセット3箇所に、NOPパッチ（`MOV X0, X0`）がないか |
| システムコール | `/proc/<pid>/mem` への `open()`/`write()` が、miglogdとiked間で発生していないか |
| 診断ログ | `diagnose debug crashlog read` で、miglogd/iked/syslogdのSignal 11クラッシュがないか |
| 設定監査 | `system.auto-script` オブジェクト名に、パストラバーサル文字列（`../../`）を含むものがないか |
