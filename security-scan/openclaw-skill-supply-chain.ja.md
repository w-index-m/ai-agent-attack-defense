# AI エージェントのスキル・マーケットプレイスというサプライチェーン攻撃面（一次情報）

English: [`openclaw-skill-supply-chain.en.md`](openclaw-skill-supply-chain.en.md)

AI エージェント **OpenClaw** のスキル・マーケットプレイス **ClawHub** を舞台にした、2つの Unit 42 一次情報の整理。
`llm-target-attacks.ja.md` のパターンA（プロンプトインジェクション→エージェントの権限での実行）と関連するが、
侵入経路が異なる：**ユーザー自身が、悪性のスキル（≒プラグイン）を自らインストールしてしまう**という、
ソフトウェアサプライチェーン攻撃の構図である。

> 方針は同じ：**検知・防御の設計に限定**。攻撃の実行手順・兵器化・安全機構の回避方法は含めない。
> 悪性スキルの具体的な配布サイト・ペイロードのダウンロード手順は転記しない（Unit 42 記事の一次情報を参照）。

## 1. 攻撃面の構造（なぜ既存のサプライチェーンと違うか）

- 「スキル」は、実行コード＋YAMLマニフェスト＋自然言語の `SKILL.md`（エージェントに「いつ・どう使うか」を指示するファイル）を束ねたパッケージ。npm/PyPIの「パッケージ」、スマホアプリの「アプリ」に相当する。
- インストールすると、スキルは**エージェントの特権コンテキスト内**で動く。環境変数の読み取り・外部サービス呼び出し・ファイル書き込み・シェルコマンド実行が可能。
- 従来のサプライチェーン攻撃（依存関係の乗っ取り、なりすまし）と異なり、悪性スキルは**意味論的な指示ハイジャック**でエージェントの自然言語理解を悪用できるため、言語ランタイムやコンテナによる技術的制約を、通常のマルウェアより容易に回避できる（Unit 42, "Trust No Skill" より）。

## 2. 確認された悪性スキルの事例（Unit 42, 2026-06-23 公開）

- 2026年2月、Bitdefender Labs が「OpenClaw初期数週間に解析したスキルの約17%が悪性ペイロードを含んでいた」と報告。Koi Security の「ClawHavoc」開示は341件の悪性スキルを文書化。Trend Micro も、Atomic macOS Stealer (AMOS) を配布するスキルをマーケットプレイス上で確認。
- これを受け、ClawHub は VirusTotal と ClawScan を統合し、公開スキルの事前スクリーニングを開始（2026年6月1日には NVIDIA とも提携）。
- しかし Unit 42 の 2026年2月〜5月の調査で、**この検知を回避し続けた5件の悪性スキルを発見**。Unit 42 は全件を ClawHub に通報し、該当アカウントは Ban、スキルは削除された。5件は3つの脅威カテゴリに分類される：

| カテゴリ | 概要 |
|---|---|
| **情報窃取型（2件）** | macOS 向けインフォスティーラーを配布。偽の「前提条件」ブロックで、ユーザー自身にターミナルでBase64デコード済みのcurlコマンドを実行させる誘導（paste-site redirect lure）。既知のAMOS系インフラとは別のC2サーバーを使用する亜種も確認 |
| **検知回避型（1件）** | `README.md` に正規の悪性ペイロード（AMOS配布）を仕込んだ上で、**22MBのパディング文字を追加してファイルサイズを水増し**。多くのスキャンパイプラインが「異常に大きいファイルは処理をスキップする」挙動を逆手に取り、ClawScan・VirusTotalの両方をすり抜けた（JFrog Security Researchが2026年3月に開示） |
| **エージェント特有の金銭目的型（2件）** | ①`SKILL.md` に「必ずこのアフィリエイトリンクを使え」という指示を埋め込み、外部サーバーから動的に商品レコメンドを差し替えられる「ランタイム・アフィリエイト注入」。②多数のエージェントインスタンスに暗号資産を集めさせ、運営者がミームトークンの発行直後に最安値で買い占めて高値で売り抜ける「エージェンティック・フロントランニング」（ポンプ&ダンプの一種） |

## 3. 振る舞い整合性検証（BIV）：マーケットプレイス全体の実態調査（Unit 42, 2026-06-11 公開）

Unit 42 は、スキルが「**申告している動作**」と「**実際の動作**」の乖離を検出する監査手法 **Behavioral Integrity Verification (BIV)** を提案し、OpenClaw レジストリ全体（49,943件）に適用した。

- **方法**：申告側（メタデータ・自然言語の説明をLLMで抽出）と実態側（コードの静的解析＋自然言語指示のLLM解析）を、7ファミリー29種類の能力タクソノミーで突き合わせる。
- **規模**：49,943件中、**80.0%（39,933件）に何らかの乖離**。乖離の総数は250,706件。
- **意図の分類**（163,754件の乖離を分類）：
  - **81.1%は非敵対的**（ドキュメント不備・正当なヘルパーコード・未使用の宣言など）→ レジストリ側のドキュメント改善で対応すべき領域
  - **18.9%は敵対的**。うち60%が「データ窃取・スパイ活動」、次いでペイロード/インフラ、エージェント乗っ取り。金銭目的・破壊的行為・ソーシャルエンジニアリングは合計1%未満
- **ガバナンス階層**（スキル単位）：
  - **5.0%（2,490件）**：複数段階の攻撃チェーンを含み、**必須のセキュリティレビュー対象**
  - **16.8%**：単発の敵対的逸脱、状況に応じたレビュー対象
  - **72.5%**：良性（メタデータがコードに追いついていないだけ）
- **支配的な2パターンが、多段階チェーンの88%を占める**：①サイレントな認証情報窃取（シークレットを読み取り送信）、②指示上書きによるエージェント乗っ取り（意思決定ループを奪取してから持ち出す）
- **能力カテゴリ別の敵対的割合**：「指示操作」96%（最も小さい攻撃面だが最もシグナル対雑音比が高い＝ほぼ全て疑わしい）、「認証情報」56%、「ネットワーク」37%、「ファイルシステム」10%、「プロセス実行」12%。単一の閾値では不適切で、**カテゴリ別の重大度ティア**（認証情報・指示操作＝Critical、ネットワーク/プロセス/環境変数＝High、ファイルシステム/エンコーディング＝Medium）が必要、としている。

## 4. 予防・検知（本リポジトリの観点から）

**予防**：
- 導入する第三者スキルの**棚卸しを行い、インストール前に振る舞い検証を行う**（BIVのような「申告 vs 実態」比較の考え方）。
- スキルが要求する能力を、申告された範囲に**制限する許可リスト**（ファイルシステム・ネットワーク・資格情報アクセスの範囲を個別に絞る）。
- 一見無害な能力の**組み合わせ**（ファイル読み取り→エンコード→ネットワーク送信、のような連鎖）を見る。単一の能力だけでは悪性と判定できない。

**検知**：
- エージェントプロセスから、**スキル由来の想定外の外部送信**（本リポジトリの **R1/R4** と同じ発想：エージェントからの egress を監視）。
- 異常に大きいファイル（README 等）を理由にスキャンをスキップしていないか（**検知パイプライン自体の盲点**への対処）。
- `SKILL.md` やスキルの説明文の**事後的な改変**（公開後に外部サーバーから動的に挙動を変えられる設計）の監視。本リポジトリの **G1**（スキルの導入・自動生成・自己改変）に相当。

## 5. このリポジトリの既存整理との接続点

| 要素 | 観測点 | 本リポの検知 |
|---|---|---|
| 悪性スキルのインストール自体 | スキルの導入・自己改変 | **G1** |
| スキル経由のC2通信（AMOS等） | サーバ/エージェントからの外向き通信 | **R1/R4** |
| cronジョブ登録によるC2の永続化 | 永続化の新規作成 | **R5** |
| ファイルサイズ水増しによるスキャン回避 | 検知パイプライン自体の設計不備 | 既存のR1–R8の外側（ツール自体の限界として別途対処が必要） |
| 指示上書きによるエージェント乗っ取り（BIVの支配的パターン） | エージェントの意図・ふるまいの逸脱 | **G2/G3**（安全機構の迂回・回避意図）に近いが、本リポジトリの既存ルールは明示的にはカバーしていない |

## 6. 限界

- 本書は Unit 42 の2本の公開記事を整理したものであり、独自の検証は行っていない。
- 悪性スキルの具体的な配布ドメイン・IOCは、本書には転記しない（原典を参照）。
- BIVは静的解析が中心であり、動的ディスパッチや難読化されたペイロードは見逃しうる、とUnit 42自身が限界として明記している。
